# Desktop: первый рабочий срез

Ветка: `codex/desktop-workspaces`. Исходная база: `bb5f967`.
Платформа проверки: macOS arm64. Статус: технический preview.

## Что реализовано

- Electron 44.4.5 с текущим smithy-web, список проектов и отдельные WebContentsView.
- Ленивый запуск, переключение без остановки агентов, Stop/Restart/Remove/Logs.
- Отдельный Node 22.23.3 на проект; независимые cwd, конфигурация и uploads.
- Явное окружение backend, без служебной идентичности родительской агентской сессии.
- IPC запуска/остановки, порт от ОС, projectId + instanceId + секрет.
- Проверка идентичности до загрузки интерфейса, авторизация HTTP/SSE/WS.
- Блокировка базы для новых Desktop и `sf serve`; проверка старых владельцев
  через macOS lsof; корректное закрытие и экспорт при штатной остановке.
- `.app` с собственными runtime, native dependencies, CLI и web assets.
  Найден и исправлен дефект копирования pnpm symlinks: стандартный extraResource
  оставлял абсолютные ссылки в staging. Теперь ссылки сохраняются относительными,
  сборка отклоняет любую ссылку за пределы bundle.

Никакие рабочие пользовательские проекты в тесты не добавлялись. Установленный
глобальный `sf` и основной checkout не переводились на экспериментальную ветку.

## Обработка новых папок и CLI из агентов

- Add project предлагает `sf init`, если базы нет, с выбором Review/Auto/Approve.
  Существующая конфигурация при частичной инициализации сохраняется. Отмена ничего
  не создаёт; ошибки показываются нативным диалогом поверх WebContentsView.
- Найден пробел: сетевые команды CLI сохраняли fallback на localhost:3457.
  В Desktop они теперь используют приватный descriptor текущего server.lock,
  проверяют project/root/instance и отправляют авторизацию. Противоречащий
  `--server` отклоняется; старая агентская сессия не принимает новый instanceId.
  Обычные команды задач/документов используют локальную SQLite через STONEFORGE_ROOT.
- Проверены реальный bundled CLI из cwd другого проекта и чужие legacy URL: меняется
  только нужная база/агент. Чужой --server и старый instanceId отклоняются.
- Проверки этого исправления: 2 desktop integration tests, 15 context/config,
  83 CLI/provider compatibility, 7 transport/serve; typecheck 17/17. Packaged Add
  покрывает отмену, инициализацию, клавиатуру, повторное добавление и видимую ошибку.
  Повторный LaunchServices smoke test прошёл.
- Это изменение касается встроенного CLI Desktop. Старый глобальный CLI и
  unmanaged standalone серверы не получают эту гарантию автоматически.

## Проверки и результаты

- Три настоящих backend с копиями одной тестовой базы: одинаковые ID директоров,
  workers и задач. Изменения и назначения независимы; назначение в A оставляет B
  нетронутым. Чужие credentials и старый instanceId отклоняются.
- Повторная регистрация через symlink возвращает тот же проект. Конкурирующий
  `sf serve` не получает владение базой. Потеря parent IPC закрывает backend.
- Перенесённая в `~/Applications` сборка прошла запуск через LaunchServices с
  минимальным PATH и кириллицей/пробелами в пути проекта. Аварийное завершение
  родительского приложения закрывает backend и освобождает lock.
- В собранном Electron работают существующий интерфейс, WebSocket и EventSource
  с инъекцией заголовков; хранилища трёх проектов разделены, переключение проверено.
- Общий typecheck: 17 задач прошли. Smithy: 1605 passed, 19 skipped; отдельные
  новые/затронутые транспортные и CLI проверки: 7 passed.
- Claude Code 2.1.282 ответил через настоящий PTY внутри `.app`. Последняя
  повторная проверка перенесённой сборки достигла лимита пользовательской сессии;
  дополнительные live-запросы остановлены. Повторять после сброса лимита.
- Codex CLI 0.157.0 ответил в раннем прогоне упаковки; поздние повторные прогоны
  возвращают provider HTTP 401. Отдельный обычный `codex exec` вне Desktop
  воспроизводит тот же 401, хотя login status сообщает ChatGPT. Текущий совместный
  live-прогон обоих провайдеров **не считается прошедшим**; авторизация не менялась.
- Нативная ручная проверка окна через accessibility недоступна, пока Mac заблокирован.
  Автоматические проверки Electron и изображения отдельных renderer выполнены.

Историческое смешение трёх старых инстансов не воспроизведено. Не приписываем его
портам или найденным общим путям: установлена необходимость проверяемой изоляции,
а не первопричина давнего сбоя.

## Следующий срез до ежедневного использования

1. Сохранять UI-настройки по projectId независимо от меняющегося origin/порта.
   Сейчас browser partitions разделены, но после перезапуска backend настройки
   старого origin не мигрируют. Базы и agent session state от порта не зависят.
2. Безопасное восстановление stale lock и воспроизведение terminal history после
   падения renderer. Пока views сохраняются при переключении и не выгружаются.
3. Общие лимиты агентов и ясная диагностика недоступных providers; чтение логов
   предыдущего запуска из интерфейса (ограниченные файлы логов уже сохраняются).
4. `sf open`, повторное открытие проекта из второго запуска, обработка sleep/wake,
   долгий прогон и ограничения памяти большого числа views.
5. Полный повторный live-прогон после восстановления авторизации Codex, включая
   headless workers/resume и многопроектные рабочие цепочки.
6. Подпись/notarization, проверки обновления/отката и длительная приёмка.

Менеджер пока находится в `apps/desktop/src/manager.ts`, независимо от Electron API.
Выделение в отдельный пакет имеет смысл после стабилизации его протокола.
